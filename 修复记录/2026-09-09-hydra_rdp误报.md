# 2026-09-09 — hydra RDP 模块对 xrdp 误报（假密码被报成命中）

> 索引：[修复记录/README.md](README.md)

**背景：** 用户报告 hydra_brute 的 RDP 模块对 xrdp 产生误报。实测确认。

**复现证据（实测，100.101.108.100 = xrdp，仅 2 次尝试）：** 用现编的假密码文件（`WrongPass123`、`NotThePassword`——机器上绝无可能存在）打 3389，hydra 输出：

```
[WARNING] the rdp module is experimental. ...
[3389][rdp] host: 100.101.108.100  login: probeuser  password: NotThePassword
[STATUS] attack finished ... (valid pair found)
1 valid password found
```

两次验证分别命中两个不同的假密码（第一次 `NotThePassword`、第二次 `WrongPass123`），进一步证明是**协议应答解析缺陷导致的随机误报**，而非某个密码碰巧对了。hydra 官方自己把 rdp 模块标记为 experimental。wrapper 原样把误报当战利品呈现，agent 会直接采信。

**根因（pentest.py `hydra_brute`）：** 工具对 `service=rdp` 没有任何风险标注，hydra 的 experimental rdp 模块对 xrdp（Linux 上最常见的 RDP 实现）误报率极高，输出被原样呈现。

**修复：** `service == "rdp"` 时在输出头部（免责声明之后）追加醒目警告块：rdp 模块为实验性、对 xrdp 频繁误报（附 2026-09-09 实测复现说明）、**任何 rdp 凭据都不得直接使用**，必须人工验证（如 freerdp 实际登录），或换用更可靠的服务模块（ssh/smb/http-form）。

**验证：** 线上 MCP `service=rdp` → 输出头部含 `🔴 RDP 误报警告（重要）…`；`service=ssh` → 无该警告。新增 2 个回归测试。

**测试：** 715 通过（唯一失败为预存的 patch_audit 问题）。
