# 2026-08-28 IPv6 工具扩展：4 新工具 + 4 项增强

IPv6 家族从"单机诊断"升级为"局域网级工具"。新增 4 个 🟢 工具
（设备发现 / 全链路体检 / RA 监听 / 路由诊断），并对 4 个既有工具做增强
（拓扑合并 NDP、status 配置来源分析、流量统计 v4/v6 分布、ddos 增 icmpv6 方法）。
工具总数 62 → **66**，IPv6 工具 6 → **10**。

## ✨ 新增

### `ipv6_scan` — IPv6 设备发现
- **被动层**：NDP 邻居表（`ip -6 neigh`）— 所有与本机通信过的 v6 设备
- **主动层**（可选）：`nmap -sn -6` 扫指定小前缀（`/80` 或更小，`/64` 有 2^64 个地址无法全扫，输入校验强制限制），
  或自动模式下 `auto_sweep=true` 扫本机每个 /64 前缀的前 16384 个地址
  （`/128` 点对点地址如 Tailscale 自动排除，链路本地自动带 `%iface` zone）
- **对照层**：与 IPv4 `arp-scan` 结果按 MAC 对照 — 只出现在 v6 的设备标 🔮"仅 IPv6 可见"
  （这类设备 IPv4 ARP 永远扫不到）

### `ipv6_doctor` — 一键全链路体检
按依赖顺序跑 5 层，逐层给结论，直接指出"断在哪一层"并建议下一步工具：
`L1 本机地址 → L2 默认路由 → L3 AAAA 解析 → L4 公网 ping → L5 v6 HTTP 出口 IP`
（L5 用 `curl -6 https://6.api.ipify.org` 拿出口地址；上游层不过则下游层 ⏭️ 跳过）。
每层附原始输出证据。

### `ipv6_ra_inspect` — 路由器通告监听
被动抓 RA（`tcpdump -i <iface> 'icmp6[0] == 134'`，默认 30s）并解析：
通告前缀（SLAAC 来源）、M/O 标志（DHCPv6 有状态/无状态）、MTU、router lifetime、源 MAC。
给出结论：M=1 有状态 DHCPv6 / O=1 无状态 DHCPv6 / 通告前缀 → SLAAC /
**RA 存在但不通告前缀 → "IPv6 半开"诊断**（设备只能拿到 fe80）。
抓不到 RA 时给出"RA 周期 4-18 分钟，可延长监听；长监听仍空 = 路由器没发 RA"的指引。

### `ipv6_route_debug` — 路由/源地址选择诊断
`ip -6 route get <目标>`：选哪个源地址（含分类）、下一跳、出口网卡、metric，
并列出出口网卡上的本机地址。域名先解析 AAAA（无 AAAA 直接给结论）；
无路由时（`RTNETLINK answers: Network is unreachable`）给诊断建议。
默认目标 `2400:3200::1`（公共 DNS）。

## 📝 改动（既有工具增强）

### `network_topology` / `snmp_topology` 合并 NDP 邻居
- 两个拓扑现在都会并入 `ip -6 neigh` 邻居表：MAC 不在 IPv4 ARP 表中的设备
  标为 `🔮 ipv6-only`，进拓扑图 + 单独"仅 IPv6 可见设备"小节
- 共享逻辑放在 `netinfo.py`（`ndp_devices` + `merge_ndp_devices`），延续公共层约定
- **顺带修了一个渲染隐患**：Mermaid 节点 ID 原来直接 `ip.replace(".", "_")`，
  v6 地址带冒号会破坏节点 ID — 新增 `_safe_node_id` 统一清洗（v4 输出不变）

### `ipv6_status` 增加配置来源分析
地址解析现在捕获 scope + 内核标志（dynamic/mngtmpaddr 等），新增
"地址配置来源分析"表：静态/手动、SLAAC（含隐私扩展临时地址判定）、
SLAAC or DHCPv6（单地址无法区分时提示用 `ipv6_ra_inspect` 确认）、mngtmpaddr 提示。

### `traffic_stats` 增加 v4/v6 分布
新增 `_PKT6_RE` 解析 `IP6` 行（v6 端点端口以点连接 `2408::1.443`，
`_split_v6_endpoint` 拆分），头部新增 `**v4/v6 分布:**` 行；
`_normalize_proto` 识别 `ICMP6` → `ICMPv6`；v6 源/目的地址进 Top talkers。

### `ddos_attack` 增加 `icmpv6` 方法（🔴 gated，需 PENTEST_ENABLED）
`hping3 -6 --icmp` ICMPv6 echo flood；`DdosInput` 加 model_validator：
`method=icmpv6` 时 target 必须是合法 IPv6 地址（带 zone 亦可）。
`mixed` 保持纯 v4 语义不变。

## 🔧 修复

- Mermaid 节点 ID 对含冒号的 v6 地址不安全（见上，新增 `_safe_node_id`）
- **executor 超时时丢失全部部分输出**（实测发现）：原实现 `wait_for(proc.communicate())`
  超时会取消管道读取协程，随后 kill 进程再二次 `communicate()` 只能拿到 0 字节
  （Kali 日志实证：`Command timed out after 22s (partial: 0 chars)`，而当时 tcpdump 正在抓包）。
  改为流式 pump：两个管道并行读取、边到边存入列表；超时后 kill + 有界 drain，
  **保留 kill 前已 flush 的全部输出**（修复后 `traffic_stats` 同场景 0 包 → 48 包；
  `tests/test_executor.py` 回归测试守护）
- **tcpdump 工具无时长上限**：`traffic_stats` / `ipv6_ra_inspect` 原来靠 executor
  `duration+10` 的 backstop kill 收尾，实际耗时超请求值（12s→22s / 20s→30s）且部分输出被丢；
  现用 `timeout -s INT {duration}` 包裹 — SIGINT 使 tcpdump 优雅退出并打印统计
  （rc 124），另加 `-l` 行缓冲，即使 backstop 触发也不丢数据；实测耗时 = 请求值
- 无其它行为变化：v4 路径输出与重构前逐字节一致（测试守护）

## 🐛 实测发现（写代码前在 Kali 抓真实输出校准解析）

- **Kali 家庭网段 180s 内 0 个 RA** — 家用路由器根本没在 LAN 发 RA，
  这正是 Kali 只有 fe80 链路本地、没有 ULA/公网 IPv6 的根因
  （`ipv6_ra_inspect` 的"抓不到 RA"诊断路径因此有了真实场景）
- tcpdump 4.99.6 的 RA 解码格式与文档常见示例不同：`Flags [managed, other stateful]`、
  `prefix info option (3), length 32 (4): <prefix>, Flags [onlink], valid time ...s, pref. time ...s`、
  选项后跟 `0x0000:` hex dump 行 — 正则按实测样本编写（测试样本即真实抓包）
- `ip -6 route get` 无路由时 rc=2 且输出 `RTNETLINK answers: Network is unreachable`
- scapy（Kali 新版）RA 类名是 `ICMPv6ND_RA`/`ICMPv6NDOptPrefixInfo`（无 `ICMPv6` 基类导出）
