# 2026-08-28 抽取网络探测公共层（netinfo），消除 6 处重复代码并修复 2 个潜在 bug

> 本文件是 kali-mcp 的一次更新说明，记录本次**新增了什么、修复了什么、改动了什么**。
> 命名与存放约定见 [docs/updates/README.md](README.md)。

### 背景：代码审计发现的两个"屎山"问题

对全部源码做 AST 静态审计 + 人工审查，发现：

1. **`snmp_topology` 与 `network_topology` 逻辑重复**（tools.py 原 884-1300 行，约 420 行）：ARP 解析、设备分类、Mermaid 渲染各写了两遍。`snmp_topology` 里注释写着 "Reuse ARP topology code"，实际是复制粘贴——且两份已**分叉**：子网探测触发条件不同（一个把显式 `192.168.0.0/24` 当未指定）、ARP 解析数据结构不同（dict vs tuple）、渲染行为不同（多网关+AP 挂接 vs 单网关平铺）。
2. **子网/网关探测代码块重复 6 次**（tools.py×2、monitor.py×2、pentest.py×2）：`ip route → dev → ip addr → inet → IPv4Network` 同一段逻辑散在 4 个文件里，失败回退策略还各写各的。

### ✨ 新增

新模块 `src/kali_mcp/netinfo.py` —— 本机网络探测与 ARP 分析的**唯一公共层**：

| 函数 | 职责 | 替代的重复代码 |
|------|------|----------------|
| `detect_default_iface(executor)` | 默认路由网卡（`ip route → dev`），兜底 `eth0` | 6 处探测块的第一步 |
| `detect_subnet(executor, subnet)` | 显式子网优先；否则自动探测，统一失败回退 `192.168.0.0/24` | 3 处完整子网探测（含 2 个已分叉变体） |
| `detect_gateway(executor, target)` | 默认路由网关（`ip route → via`），回退 `网段+.1` | pentest.py 里逐字节相同的 2 份拷贝 |
| `classify_device(vendor)` | 厂商名 → (类别, 图标)（原 `_classify_device` 迁入，顺带删掉一个恒真的 `if` 分支） | tools.py 原私有函数 |
| `arp_scan_devices(executor, subnet)` | `arp-scan` 扫描 + 解析 + 分类，返回 `(原始结果, 设备dict列表)`，MAC 统一大写 | 2 份 ARP 解析（dict/tuple 两种分叉写法） |
| `arp_mermaid_lines(devices)` | 共享 Mermaid 渲染：Internet → 网关 → AP → 设备 | 2 份已分叉的渲染逻辑 |
| `arp_class_stats_lines(devices)` | 设备类别分布表 | 2 份统计表 |

### 🔧 修复（重构顺带消灭的潜在 bug）

- **`network_topology` 无网关时崩溃（NameError）**：旧代码 `gw_id` 只在 `for g in gateways` 循环里赋值，ARP 扫不出 `.1` 网关但扫出其他设备时，后续引用 `gw_id` 直接抛 `NameError`，整个工具崩掉。共享渲染里 `gw_id` 有确定性的兜底值（占位节点 `gw`），并新增回归测试 `test_no_gateway_does_not_raise`。
- **`TopologyInput.subnet` 默认值语义混乱**：字段默认值写死 `"192.168.0.0/24"`，导致代码里出现 `if not subnet or subnet == "192.168.0.0/24":` 这种"把默认值当未指定"的黑魔法，且与 `snmp_topology` 的行为不一致（后者尊重显式传参）。现默认值改为 `""`（空 = 自动探测），与其他工具统一，`detect_subnet` 里一行判空搞定。
- **`network_topology` 硬编码假指标**：输出里写死的 `扫描耗时: 2-3s` 改为 `time.monotonic()` 实测值。
- **`snmp_topology` 死变量**：`gw_vendor` 赋值后从未使用，删除。

### 📝 改动

- `src/kali_mcp/tools.py`：`network_topology` 从 119 行缩到 ~40 行，`snmp_topology` 从 241 行缩到 ~180 行；删除 `_DEVICE_CLASSES`/`_classify_device`（迁入 netinfo）；`TopologyInput.subnet` 默认值 `192.168.0.0/24` → `""`。
- `src/kali_mcp/monitor.py`：`network_diff`、`nethogs_bandwidth` 的探测块各缩成 1 行调用。
- `src/kali_mcp/pentest.py`：`arpspoof_mitm`、`arpspoof_disconnect` 的网关探测各缩成 1 行调用，顺带删掉 2 个只为探测服务的函数内 `import re as ...`。
- `tests/test_netinfo.py`（新增）：23 个用例，用 FakeExecutor 覆盖探测回退链、ARP 解析/分类/MAC 大写/`.1` 网关启发式、Mermaid 渲染层级、**无网关不崩溃回归**、空设备边界。
- **测试：156 passed**（原 133 + 新增 23）。
- 工具总数不变（62），所有工具签名与输出结构兼容（`network_topology` 输出新增真实耗时；SNMP 失败时的 ARP 降级图升级为与 `network_topology` 相同的层级渲染——**行为增强，非破坏**）。

### ✅ 行为一致性说明

| 场景 | 旧行为（不一致） | 新行为（统一） |
|------|------------------|----------------|
| 显式传 `subnet="192.168.0.0/24"` | `network_topology` 无视、`snmp_topology` 尊重 | 两者都尊重 |
| 探测失败 | 有的静默、有的回退 /24 | 统一回退 `192.168.0.0/24` + warning 日志 |
| 无网关的 ARP 图 | `network_topology` 崩、`snmp_topology` 降级图缺层级 | 都不崩，统一层级渲染 |
